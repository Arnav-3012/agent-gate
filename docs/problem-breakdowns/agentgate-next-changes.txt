LEAVES:
[1] Metric validity (sentence answers)
  type: LLM eval > answer correctness > LLM-as-judge replacing token-F1
  why: finance gold answers are sentences; sample: correct "$1,824 million" scored 0.22; 22/60 RAG rows F1<0.05 in both models; EM = 0.0 everywhere
  why_not: not EM/F1 (format-sensitive) | not ROUGE/BLEU (same failure) | not human-only (n too big to scale, but needed for validation)
  approaches: keep F1 + finance_f1 for numerics (baseline) | local 14B judge (free, self-preference) | hosted Haiku judge reference-guided (D42, best, needs key+go)
  pick: hosted judge on sentence Qs, validate on 30 hand-labelled rows, kappa>=0.6 else fall back; keep numeric Qs on finance_f1
  concept: Cohen kappa = (p_o - p_e)/(1 - p_e), agreement beyond chance; a judge is a classifier whose accuracy must be measured before use
  trap: judge model grades its own family's answers higher (self-preference); trusting judge without human labels
  eval: kappa vs human on stratified 30 rows; report judged-F1 next to token-F1
  confidence: high

[2] Retrieval recall (finance)
  type: RAG > retrieval > recall@k improvement (hybrid + rerank + metadata filter)
  why: rag_hit 21/60 = 35%; 7B RAG F1 0.32 on hit vs 0.14 on miss; general rag_hit 23/30 = 77% (F1 0.62 vs 0.29); agent does not rescue misses (0.16 vs 0.14 finance 7B). Sample: Boeing Q answered "no legal battles" = wrong chunk retrieved.
  why_not: not a model-size problem (14B misses equally: 21/60 both) | not a prompt problem (hit/miss gap is large and mechanical)
  approaches: raise top_k 5->8 (cheap baseline) | metadata filter on company+fiscal year parsed from the Q (FinanceBench Qs name both) | hybrid BM25+dense + cross-encoder rerank (heavy, needs install approval)
  pick: metadata filter first (free, high leverage), then top_k 8, then hybrid/rerank only if recall@k still <70%; apply to every arm
  concept: recall@k = fraction of Qs whose gold chunk is in top-k; end-to-end F1 <= f(recall); measure retrieval separately from generation
  trap: tuning prompts/router while 65% of Qs never see the answer
  eval: recall@5 and @8 on the 60 finance Qs (rag_gold), then F1 split hit/miss
  confidence: high

[3] Agent arm validity
  type: LLM agent > loop budget/stopping criteria audit
  why: finance agent stop=max_tokens in 36/60 (7B) and 21/60 (14B); budget 6000 tok vs ~5k mean usage; 60% of 7B finance agent runs were cut off before answering confidently; "agent loses" is partly a budget artefact
  why_not: not proof agent is bad (confounded) | not necessarily raise cap blindly (cost explosion)
  approaches: leave as is and disclose (cheap) | raise budget to ~9-10k and rerun a subset (tests the confound) | replace with fixed 2-step corrective-RAG (retrieve -> if low score rewrite query -> retrieve again), which is a pipeline not an agent
  pick: rerun agent on a subset with higher budget AFTER the retrieval fix; if still dominated, drop agent from the headline and keep as a measured negative result; add corrective-RAG arm as the cheap "retry" arm
  concept: agent value = P(retry fixes bad first retrieval) - P(retry breaks good retrieval); a budget cap truncates the retry before it can pay
  trap: concluding "agents are useless" from runs truncated by your own cap
  eval: stop-reason histogram (target: max_tokens < 10%), F1 vs cost at 2 budgets
  confidence: medium (need to read agent loop code to confirm stop semantics)

[4] Statistical power and honest comparison
  type: stats > paired comparison + held-out router evaluation
  why: n=40/30, per-arm CI half-width ~0.06-0.16, arms overlap; oracle-router = max of 4 noisy arms on the same Qs -> upward biased (+0.06 finance, +0.07 general)
  why_not: not per-arm CIs (overlap tells nothing about differences) | not oracle as an estimate (it is a ceiling)
  approaches: more Qs (Phase 3: ~300 general + 100 finance) | paired bootstrap of F1 differences | cross-validated router (fit labels on folds, score held-out)
  pick: all three; headline = held-out router vs best fixed arm with paired CI
  concept: paired bootstrap resamples questions, recomputes mean(F1_A - F1_B); CI of the difference excludes 0 -> real
  trap: ranking arms by point estimates inside overlapping CIs; selecting router thresholds on the test set
  eval: CI of (router - best fixed) on held-out folds
  confidence: high

[5] Router design
  type: routing > cost-aware cascade over arms
  why: agent dominated, so real choice = 7B RAG vs 14B RAG (+ optional retry arm); general: 14B RAG 0.656 vs 7B 0.544 (+0.11 for 2x cost); finance +0.03 (noise) at 2x cost
  why_not: not a learned multi-class router yet (labels too noisy at n=40) | not RAG-vs-agent as the headline (dominated)
  approaches: always-7B RAG (baseline) | cascade: 7B RAG, escalate to 14B if confidence/retrieval score low | learned classifier on query features (needs ~300+ labels)
  pick: cascade with serve-time signals (top-1 retrieval score, score margin, answer abstention/length, model logprob if available); fit threshold by CV
  concept: cost-quality Pareto; router is useful iff separable signal exists at serve time (gold answers do not)
  trap: labels from offline F1 that a serve-time router cannot see
  eval: held-out F1 vs $/1k vs always-7B and always-14B; escalation rate (health ~5-30%, check vs oracle)
  confidence: medium (depends on [1],[2] results)

KEY_FORMULAS:
  kappa = (p_o - p_e) / (1 - p_e)
  recall@k = (# Qs with gold chunk in top-k) / N
  agent_wins iff P(first retrieval bad)*P(retry fixes) > P(retry breaks good retrieval)
  paired diff CI: bootstrap over Qs of mean(F1_A - F1_B)
  cost per 1k = 1000 * mean(tokens_in*p_in + tokens_out*p_out)
