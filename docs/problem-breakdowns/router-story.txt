PROBLEM: make AgentGate's router story meaningful after 6 null signal tests on near-duplicate arms
DOMAINS: ML(routing = cost-sensitive clf / uplift) + stats(noise null, paired CI) + LLM eval + product story
IN: query (+ retrieval)   OUT: arm choice   SUCCESS: held-out router beats RANDOM routing at same cost AND oracle excess over noise null > 0
GIVENS: general 300 Qs (HotpotQA bridge/comparison/single), finance 100; judged scores (Haiku, kappa .84); local 7B/14B Qwen RAG+agent; Haiku 5.5 $0.10/$0.50 per 1M; budget tiny
HIDDEN_REQS: claims must survive random-routing control; arms must differ in capability AND cost or no router can win
ASSUMPTIONS: Sonnet 5.5 price $2/$10 per 1M (aggregators; $3/$15 also listed) -> VERIFY on platform.claude.com before using
OPEN_QS: is HotpotQA near-ceiling for Haiku (then strong rung adds little)? does closed-book 7B beat RAG on popular-entity Qs?

BIG_PICTURE: routing value = (variance of per-query uplift) x (cost gap). Current arms: same family, same retrieval, cost gap 2x, judged 7B~14B (+0.018 ns) -> both factors ~0 -> null is EXPECTED, not a bug. Literature agrees: LLMRouterBench (2026, 400K instances) finds many routers incl. commercial fail to beat simple baselines; RouteLLM wins only with a big weak/strong gap (Mixtral vs GPT-4). Adaptive-RAG routes no-retrieval | single-step | multi-step by query complexity.
KEY INSIGHT: turn the null into the experiment. 2 arm sets, same eval: (A) same-tier local arms -> router ~ random (have it); (B) cross-tier arms with 20x cost gap -> does routing pay? "When does routing help" is a defensible, novel-for-a-student result.
